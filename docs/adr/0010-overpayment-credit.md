# ADR-0010. Переплата не отклоняется, а зачитывается в следующий счёт

**Статус:** принято, 2.0.8

## Контекст
Провайдер подтверждает платёж post factum (webhook); отклонить уже списанные деньги нельзя. Ограничение `paid_amount <= amount + penalty_amount` приводило бы к падению `fn_invoice_recalc` на легитимном webhook.

## Решение
Верхняя граница снята. `invoice.overpaid_amount` — вычисляемое поле `GREATEST(paid − amount − penalty, 0)`. Счёт с переплатой переходит в `PAID`. При выпуске следующего счёта по договору billing-job добавляет строку `invoice_line.kind = OVERPAYMENT_CREDIT` с отрицательной суммой и `source_invoice_id`; уникальный индекс `uq_invoice_line_overpay_source` гарантирует однократный зачёт. Если договор в `EXPIRED`/`TERMINATED` — создаётся `task` типа `MANUAL` «Вернуть переплату».

## Отклонённые альтернативы
Отклонять платёж (невозможно для webhook); автоматический refund (комиссия провайдера, юридические риски).
