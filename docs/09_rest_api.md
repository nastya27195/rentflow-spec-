# REST API
Базовый URL `https://api.rentflow.ru/v1`, аутентификация OAuth 2.0 Bearer, пагинация `page/size`,
ошибки в формате `{code, message, details}`. Полный контракт — `api/openapi.yaml`.

Детальная постановка `POST /invoices/{id}/payments`: заголовок Idempotency-Key обязателен;
счёт должен принадлежать арендатору из токена (403), быть в статусе ISSUED/PARTIALLY_PAID (409); просроченный счёт (`overdue_since`) оплачивать можно,
сумма ≤ остатка долга (422); создаётся Payment PENDING и возвращается ссылка на оплату шлюза (201).
Повтор с тем же ключом возвращает сохранённый ответ (200).

## Аутентификация и пользователи (2.0.12)

Эндпоинты `auth` не требуют Bearer-токена (`security: []`), остальные — требуют.

| Метод и путь | Назначение | Коды |
|---|---|---|
| `POST /auth/login` | Вход по e-mail и паролю → `TokenPair` (access JWT 15 мин + одноразовый refresh 30 дней). Проверка пароля — argon2id против `user_account.password_hash`; обновляется `last_login_at`. | 200, 401, 422, 429 |
| `POST /auth/refresh` | Ротация токенов по refresh-токену; использованный refresh инвалидируется, повторное предъявление — 401 и отзыв всей цепочки. | 200, 401 |
| `POST /auth/invitations/{token}/accept` | Принятие приглашения (FR-51): пользователь задаёт пароль по одноразовой ссылке (TTL 72 ч), хэш argon2id записывается в `password_hash`, токен помечается использованным, возвращается `TokenPair`. Истёкший/использованный токен — 410. | 200, 410, 422 |
| `GET /users/{id}` | Карточка пользователя (`User`). ADMIN видит пользователей своей организации (RLS по `organization_id`), MANAGER/TENANT — только себя (403). Схема `User` закрыта (`additionalProperties: false`) и не содержит `password_hash`. | 200, 403, 404 |

Приглашение создаётся администратором вне REST-контракта v2 (админ-консоль / внутренняя команда) — см. `15_open_questions.md`.
