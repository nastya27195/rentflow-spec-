# Функциональные требования
## Объекты и арендаторы
- FR-01. Менеджер может создать, изменить и архивировать объект.
- FR-02. Менеджер ведёт карточку арендатора с контактами и реквизитами.
- FR-03. Архивирование объекта запрещено при наличии активного договора.
## Договоры
- FR-10. Договор создаётся в статусе DRAFT с обязательными полями: объект, арендатор, ставка, период биллинга, даты.
- FR-11. Активация переводит договор в ACTIVE и задаёт next_billing_date.
- FR-12. Приостановка (SUSPENDED) останавливает биллинг.
- FR-13. Расторжение (TERMINATED) возможно при отсутствии неоплаченных счетов либо с подтверждением.
- FR-14. По окончании срока договор переходит в EXPIRED.
## Биллинг
- FR-20. Ежедневно в 00:05 система формирует счета по договорам с next_billing_date ≤ today.
- FR-21. Повторный запуск за ту же дату не создаёт дубликатов (уникальность contract_id + period).
- FR-22. Счёт выставляется со сроком оплаты due_date = issue_date + grace_days.
- FR-23. При `due_date + grace_days < today` (в часовом поясе организации) и незакрытом долге overdue-job проставляет счёту `overdue_since` (статус оплаты не меняется, ADR-0005) и публикует `InvoiceOverdue` ровно один раз.
- FR-24. Пеня начисляется ежедневно как % от остатка долга.
- FR-25. Менеджер может скорректировать счёт до оплаты.
## Платежи
- FR-30. Арендатор может оплатить счёт в статусе ISSUED или PARTIALLY_PAID (в том числе просроченный — с `overdue_since`).
- FR-31. Инициация оплаты идемпотентна по Idempotency-Key.
- FR-32. Подтверждение приходит webhook'ом с проверкой подписи.
- FR-33. Частичная оплата переводит счёт в PARTIALLY_PAID.
- FR-34. Платёж PENDING, по которому не пришёл webhook, переводится job'ом истечения в EXPIRED по истечении TTL платёжной ссылки провайдера (30 мин, `diagrams/state_payment.puml`); счёт остаётся доступным для новой оплаты. FAILED — только по явному отказу провайдера.
## Уведомления и задачи
- FR-40. Арендатор получает уведомления о выставлении счёта, напоминание за 3 дня и о просрочке.
- FR-41. При просрочке > 7 дней создаётся задача менеджеру.
- FR-42. Менеджер видит список задач с приоритетами.

## Дополнения v2.0


* **FR-43** Два договора ACTIVE/SUSPENDED с пересекающимися периодами по одному объекту невозможны; попытка -> 409 `property_period_conflict`.
* **FR-44** Календарные операции выполняются в часовом поясе организации; ночные job'ы — в 00:05 локального времени.
* **FR-45** События публикуются через outbox в транзакции бизнес-операции; консьюмеры идемпотентны.
* **FR-46** Ключ идемпотентности действует 24 ч в разрезе пользователя; повтор с другим телом -> 422.
* **FR-47** При деактивации менеджера открытые задачи переназначаются ADMIN организации с уведомлением.
* **FR-48** Возврат платежа пересчитывает агрегаты и может вернуть счёт из PAID в PARTIALLY_PAID/ISSUED; пеня ретроактивно не пересчитывается.

| FR-49 | Переплата не отклоняется: платёж подтверждается, счёт → PAID, `overpaid_amount` > 0. Излишек однократно зачитывается строкой `OVERPAYMENT_CREDIT` в следующий счёт договора; если договор завершён — менеджеру создаётся задача MANUAL «Вернуть переплату». | Must | ADR-0010 |
| FR-50 | Арендатор имеет тип (юрлицо / ИП / физлицо). ИНН обязателен для юрлица и ИП, для физлица — нет. | Must | UC-01 |
| FR-51 | Пользователь создаётся приглашением (`invited_at`), пароль задаёт сам по одноразовой ссылке (TTL 72 ч). Хранится только argon2id-хэш.
