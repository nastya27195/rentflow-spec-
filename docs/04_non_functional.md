# Нефункциональные требования

| ID | Требование | Значение / критерий приёмки | Как проверяется |
|---|---|---|---|
| NFR-01 | Доступность | 99,5 % в месяц (≤ 3 ч 36 мин простоя) | Мониторинг uptime, SLA-отчёт |
| NFR-02 | Время ответа API (p95) | ≤ 500 мс для чтения, ≤ 1 с для операций записи | Нагрузочный тест (k6/JMeter) |
| NFR-03 | Производительность billing-job | Обработка 10 000 активных договоров ≤ 10 мин | Прогон job на тестовом наборе |
| NFR-04 | Хранение и резервирование | PostgreSQL 15, ежедневный полный бэкап, WAL-архив, RPO ≤ 24 ч, RTO ≤ 4 ч | Регламент восстановления, тест восстановления раз в квартал |
| NFR-05 | Безопасность | OAuth 2.0, TLS 1.2+, RBAC (MANAGER / TENANT / ADMIN), изоляция данных по `organization_id` | Ревью кода, пентест перед релизом |
| NFR-06 | Аудит | Неизменяемый лог всех финансовых операций (создание/корректировка счёта, платёж, пеня) с указанием актора и времени | Проверка audit-таблиц, тест-кейсы |
| NFR-07 | Масштабирование | Горизонтальное масштабирование stateless-сервисов за API Gateway; billing-job выполняется в одном экземпляре (лидер-лок) | Архитектурное ревью, тест на двух инстансах |
| NFR-08 | Надёжность интеграций | Все входящие webhook и Kafka-события обрабатываются идемпотентно; повтор не приводит к двойному списанию | TC-03-*, раздел «Безопасность» |

Ограничения: единая валюта RUB в MVP; рабочее время billing-job — 00:05 по времени организации; интерфейс — только web (адаптивная вёрстка, без мобильных приложений).
