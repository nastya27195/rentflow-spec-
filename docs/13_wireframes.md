## Экран «Счета» — список (W-03)
Верхняя часть — четыре KPI-карточки: активные договоры, открытые счета (количество и остаток к оплате), просрочено (количество и долг), собираемость за текущий месяц (процент и прогресс-бар). Ниже — панель инструментов (поиск по номеру счёта / арендатору / договору, фильтр по статусу, кнопка «+ Выставить счёт» для разового счёта вне графика, FR-22) и таблица: номер, арендатор, договор · объект, назначение, срок оплаты (просроченный выделяется красным), сумма, пеня, к оплате, статус (цветной бейдж), действия. Под таблицей — счётчик показанных строк и остаток к оплате по выборке. Действия по счёту (W-04) доступны прямо из строки.

## Экран «Карточка счёта» (W-04)
Шапка со статусом и остатком долга; блоки «Строки счёта», «Платежи», «Пени», «История изменений». Для менеджера доступны действия «Зачесть оплату» (безналичный платёж вне шлюза, FR-33; сумма не больше остатка), «Напомнить» (повторное уведомление арендатору) и «Аннулировать» (только для счёта без оплат — бизнес-правило §9.2). Для арендатора — «Оплатить» (переход к W-07). Действия показываются только для открытых счетов (ISSUED / PARTIALLY_PAID); признак «Просрочен» выводится по `overdue_since`.

## Экраны арендатора (W-06, W-07)
W-06 показывает KPI (к оплате всего, ближайший срок, оплачено за год), предупреждение о пене при наличии просрочки, вкладки «К оплате» / «Оплаченные» со списком счетов (просроченные выделены) и таблицу истории платежей. W-07 — модальное окно оплаты: разбивка суммы (сумма счёта, пеня, оплачено ранее, к оплате), поле суммы (не больше остатка долга, частичная оплата допускается), способ оплаты (карта / СБП). При подтверждении формируется запрос `POST /invoices/{id}/payments` с `Idempotency-Key` (повторное нажатие не создаёт второй платёж), пользователь видит статус PENDING; после webhook шлюза платёж переходит в CONFIRMED и статус счёта пересчитывается (PAID / PARTIALLY_PAID), при полной оплате `overdue_since` сбрасывается.

## Интерактивный прототип
Экраны W-03, W-04 (действия по счёту), W-06 и W-07 реализованы в кликабельном прототипе `prototype/index.html` — самодостаточный HTML без внешних зависимостей, переключение ролей MANAGER / TENANT в шапке, ручное выставление счёта, зачёт безнала, имитация асинхронного подтверждения платёжного шлюза (PENDING → CONFIRMED). Экраны W-01, W-02, W-05, W-08, W-09 описаны только в таблице выше. Описание прототипа и его ограничений — `prototype/README.md`. Онлайн-версия: https://nastya27195.github.io/rentflow-spec/prototype/index.html
