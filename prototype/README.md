# Интерактивный прототип RentFlow

`index.html` — самодостаточный кликабельный прототип веб-интерфейса RentFlow: один HTML-файл без внешних зависимостей (CSS и JavaScript встроены, данные захардкожены). Открывается двойным кликом в любом современном браузере, сервер не нужен. Онлайн-версия (GitHub Pages): https://nastya27195.github.io/rentflow-spec/prototype/index.html

## Что можно посмотреть

Прототип переключается между двумя ролями кнопками в шапке.

**Менеджер УК** (экран W-03 «Счета — список» с KPI-блоком и действия по счёту из W-04, вынесенные в строку таблицы и модальные окна):
- KPI-карточки: активные договоры, открытые счета, просрочка, собираемость за месяц;
- таблица счетов с поиском по номеру/арендатору/договору и фильтром по статусу;
- действия: «+ Выставить счёт» (разовый счёт вне графика, FR-22), «Зачесть оплату» (безнал вне шлюза, FR-33), «Напомнить», «Аннулировать» (недоступно, если по счёту уже есть оплата).

**Арендатор** (экраны W-06 «Мои счета» с историей платежей и W-07 «Оплата»):
- сумма к оплате, ближайший срок, оплачено за год, предупреждение о пене при просрочке;
- вкладки «К оплате» / «Оплаченные»;
- модальное окно оплаты с разбивкой (сумма, пеня, оплачено ранее, к оплате), частичная оплата, выбор способа (карта/СБП);
- имитация асинхронного подтверждения платёжного шлюза: PENDING → CONFIRMED через ~2 с, после чего статус счёта пересчитывается (PAID / PARTIALLY_PAID); просрочка — отдельный признак overdueSince.

## Что прототип демонстрирует из спецификации

| Элемент прототипа | Раздел спецификации |
|---|---|
| Статусы счёта ISSUED / PARTIALLY_PAID / PAID / CANCELLED, признак просрочки `overdue_since` (ADR-0005) и переходы между ними | `docs/07_state_models.md`, §9.2 |
| Статусы платежа PENDING / CONFIRMED | `docs/07_state_models.md`, §9.3 |
| Частичная оплата и пересчёт остатка | FR-31, `docs/03_functional_requirements.md` |
| Подсказка про Idempotency-Key в окне оплаты | `docs/12_security.md`, §14.1; `POST /invoices/{id}/payments` |
| Ручное выставление счёта и зачёт безнала | FR-22, FR-33 |
| Запрет аннулирования счёта с оплатой | бизнес-правило §9.2 |

## Ограничения

Это прототип для демонстрации UX и бизнес-логики, а не рабочее приложение: данные живут только в памяти страницы и сбрасываются при перезагрузке, обращения к API и платёжному шлюзу имитируются таймером, аутентификации нет. Экраны W-01 «Вход», W-02 «Объекты», W-05 «Договоры», W-08 «Задачи» и W-09 «Настройки» в прототип не включены и описаны только в `docs/13_wireframes.md`; карточка счёта W-04 реализована не отдельной страницей, а действиями в строке таблицы и модальными окнами.
